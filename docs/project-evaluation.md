## 二、已完成系統的優勢

### 工程架構
- 模組拆分合理：core → combat → render → ui → main 依賴清晰
- 資料驅動：武將/裝備/關卡/章節在 `data/game-data.js` 集中管理
- 文件完善：7 份 docs 涵蓋 UI、製作、平台、參考、無障礙、廣告

### 戰鬥系統
- 完整攻擊鏈：anticipation → windup → impact → recovery
- 技能差異化：劉備治療、關羽斬、張飛擊退、趙雲殘影
- 視覺回饋：暴擊震動、hit-stop、shockwave、afterimage 等 10+ 種特效
- Boss 機制：3 波清場觸發、Banner 演出

### 像素美術
- 12 名武將全身手繪、8 種武器、7 種坐騎物種、4 種戰甲
- CSS 頭像系統極精細：每名武將獨立 clip-path + gradient 辨識度

## 六、代碼層面的問題

### 6.1 被動技能未實作

`data/game-data.js` 中每個武將都有 `passive` 欄位（如「對 Boss 傷害提高 12%」），但 `js/game/game-combat.js` 的 `applyDamage`/`makeAlly` 完全沒有讀取。玩家看到描述卻沒有效果。

### 6.2 技能特效只覆蓋 4/50

`useHeroSkill` 只對 liubei/guanyu/zhangfei/zhaoyun 有專屬效果，其餘 46 名 fallback 泛用邏輯。

### 6.3 敵將系統只有視覺

10 名 `ENEMY_GENERALS` 只在 UI 顯示名字頭像，戰鬥用通用 profile。

### 6.4 經濟膨脹風險

升級：`70 + level × 42`（線性）vs 收入：`140 + stage × 30`（線性），50 關後資源溢出。

### 6.5 排行榜假資料

`game-ui.js` L356 排名數據硬編碼。

### 6.6 CSS 檔案過大

`styles.css` 77KB（865 行），大量角色頭像 CSS 每人 30+ 行，可考慮分離為 `avatars.css`。

### 6.7 渲染模組過大

`game-render.js` 52KB（1343 行），包含所有角色繪製，可拆分武器/坐騎/身體。

### 6.8 setInterval 無清理

`game-main.js` L73-74 啟動了 `setInterval(updateHud, 350)` 和 `setInterval(persist, 5000)`，但面板打開/遊戲暫停時仍在運行。

### 6.9 innerHTML 安全

目前使用本地常數安全，但 `heroCardHtml`、`paperDollHtml` 等函數用字串拼接生成 HTML，若未來加入使用者輸入需要改為 DOM API。

### 6.10 缺少 Error Boundary

所有 JS 在全域執行，任何 runtime error 會中斷整個遊戲循環，需要 try-catch 保護 `gameLoop`。

## 十、結論

工程基礎扎實（模組化、資料驅動、像素美術全手繪、戰鬥手感佳），但要成為可上架的手遊仍有大量工作：

1. **承諾未兌現**：passive/敵將/裝備有資料但無效果
2. **缺乏基礎體驗**：無載入畫面、無新手引導、無結算畫面
3. **缺乏長期留存**：無日常任務/簽到/升星/商店/副本
4. **UI 完成度不足**：技能描述缺失、紅點系統缺失、排序功能缺失
5. **音效嚴重不足**：無 BGM、無環境音、無勝利/失敗音效

建議從 Phase 1 的 10 項開始，優先讓核心循環閉合和基礎體驗到位。
