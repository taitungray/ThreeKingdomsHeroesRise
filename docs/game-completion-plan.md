# 三國：群英再起完整遊戲完成計畫

## 目前專案盤點

### 已存在

- 直式 Web/H5 Canvas 自動戰鬥與像素角色繪製。
- 武將資料、角色差異化動作、兵種角色、技能特效、傷害數字與死亡回饋。
- 武將詳情、升級、紙娃娃四部位裝備、編隊九宮格、軍令、章節面板。
- 銅錢、糧草、玉符、主公經驗、成就、信件、紀錄與設定面板。
- Boss 波次、勝敗重整、章節推進、離線收益、localStorage 存檔。
- PWA／Capacitor 包裝、AdMob 測試設定、Android setup／start／release 腳本。
- UI／製作／平台／廣告／上架文件和基本建置檢查。

### 距離完整可玩版本的缺口

1. 章節面板只能顯示提示，尚未真正啟動指定關卡。
2. 執行邏輯已拆成 `js/game/` 五個模組，資料表獨立於 `data/`，後續功能可按邊界擴充。
3. 站位主要影響出生座標，還需要明確的前／中／後排戰鬥加成。
4. 技能需要獨立冷卻欄位，讓「每 N 次普通攻擊」不是唯一限制。
5. Boss 勝利需要更清楚的關卡結算與重打／下一關流程。
6. 需要一組不依賴視覺截圖的核心循環自動測試與 runtime smoke test。
7. 發布前仍需實機 Android build、簽名、AdMob 正式 ID、商店素材與資料安全表。

## Core Loop 定義

`啟動 → 讀取存檔 → 進入征戰 → 選擇／重打關卡 → 編隊 → 自動戰鬥 → 普通波次 → Boss → 勝敗結算 → 領取資源 → 武將／軍令成長 → 解鎖下一關 → 離線累積 → 再次進入`

### 完成門檻

- 新玩家不需要先進設定或抽卡即可看到正在進行的戰鬥。
- 任何通關都必須至少改變一項可見進度：資源、經驗、關卡、武將或成就。
- 編隊位置或武將替換必須改變戰鬥中的數值或目標行為。
- 離線獎勵必須可領取一次、存檔後重整不重複發放。
- 重新整理頁面後，關卡、武將等級、資源與陣容仍存在。

## 實作順序

### 里程碑 A：資料與文件

- 完成 `docs/reference-analysis.md`。
- 建立 `data/game-data.js`，集中 50 名武將、66 件紙娃娃裝備、軍令、20 個章節／100 個關卡資料。
- `js/game/` 按 core、combat、render、ui、main 分層，不把新關卡數值散落在 UI。

### 里程碑 B：可玩的核心循環

- 新增指定關卡入口與重打已通關關卡。
- 將目前進度與目前戰鬥關卡分離，重打不會倒退最高進度。
- 保留三波普通敵人加 Boss 的節奏，Boss 勝利解鎖下一關。
- 增加結算記錄與下一步提示。

### 里程碑 C：策略深度

- 前排：生命／防禦優勢；中排：攻擊／技能效率優勢；後排：射程／速度優勢。
- 兵種資料控制近戰、遠程、攻速、射程和技能範圍。
- 技能使用獨立冷卻，並在 HUD／角色卡上提供可理解的回饋。
- 關卡資料控制敵人組合與獎勵，而非只靠隨機生成。

### 里程碑 D：QA 與發布

- `node --check`、JSON parse、build smoke test。
- 測試新遊戲、勝利、失敗、重打、升級、改陣、存檔、離線領取。
- 以瀏覽器或 Android WebView 實際驗證按鈕與主要流程。
- 正式發布前才注入正式 AdMob ID、簽名設定和 Play Console 資料。

- 音效檔與音樂資源替換目前的 WebAudio placeholder。
- 雲端存檔、帳號系統、排行榜後端。
