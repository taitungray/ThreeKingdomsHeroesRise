# 全遊戲調整計畫

狀態：ACTIVE PRODUCT PLAN。更新日期：2026-08-28。本文件定義遊戲要收斂成什麼、先做哪些垂直切片，以及各階段如何驗收；可核對的現況放在 [目前遊戲規格](../specs/current-game-spec.md)，執行項目放在 [目前工作清單](active-backlog.md)，已重現缺陷放在 [已知問題](../issues/known-issues.md)。

## 1. 決策摘要

目前版本判定為 `FAIL／不可發布`。問題不是單一戰鬥圖或單一介面，而是五個環節同時失焦：

1. 戰鬥角色、敵人、Boss 與兵器沒有形成可信且一致的資產系統。
2. 自動戰鬥之外的配置選擇不足，編隊、戰法、裝備名義上存在，實際決策很淺。
3. HUD、對話、側欄、底欄與面板同時爭奪手機畫面，戰鬥不是視覺焦點。
4. 50 名武將、100 關與大量副系統先鋪開，但名稱、技能說明、模式深度與美術完整度未同步。
5. 現有自動測試能證明「程式有跑」，不能證明 Boss、攻擊、死亡、結算與整場畫面可接受。

因此不再以「把所有既有功能逐一美化」為目標。先建立第一章可從開局完整玩到結算、可重複驗收的垂直切片，再依相同契約擴充角色與內容。

## 2. 產品方向與體驗支柱

一句話定位：**直式、非抽卡、以五人編隊與關卡剋制為核心的三國放置小隊 RPG。**

目標玩家每次回來都應能完成：領取收益 → 判讀下一關 → 調整站位／戰法／裝備 → 觀看清楚且有身份感的戰鬥 → 做一次成長選擇 → 再挑戰。

三個不可犧牲的支柱：

- **角色可信**：不看名字也能分辨主要武將、兵種、武器與 Boss；攻擊、受擊、死亡不換人、不浮空、不出現方塊。
- **配置有意義**：站位、戰法與裝備至少各提供一個能改變戰果的選擇，失敗後知道可如何調整。
- **手機上清楚**：三秒內看懂敵我、波次／首領、主要狀態與下一個可操作項；介面不能壓住戰鬥。

## 3. 實測證據摘要

- 資料含 50 名武將，但戰鬥行為與 fallback 主要收斂到 12 組 visual template；只有 12 組完整 `skillSpecs`，其餘大量角色使用通用說明。
- 7 個 Boss 身分只映射到 4 張 Boss 圖；普通敵人與敵將亦大量借用其他武將 body，敵人錯圖是目前資料契約的結果，不是偶發載入失敗。
- 攻擊圖集自動檢查找到 1,787 個過度稀疏 cell，runtime 目前以 `ATTACK_SPRITES_APPROVED = false` 隔離。
- 裝備資料至少 66 件，但戰場兵器大量 alias 到少數通用圖與共用握點；裝備 UI 可免費輪換，尚未形成取得與取捨。
- 3×3 編隊位置會影響戰鬥與 lane bonus，但目前 UI 只能增減成員，不能調整實際位置。
- 三個戰法同時常駐，只能升級，沒有攜帶、替換或針對關卡的選擇。
- 演武、塔與副本目前主要是戰力門檻即時判定，沒有重用正式戰鬥，也沒有可觀察的策略差異。
- 自動推關會在 `startStage()` 關閉使用者正在閱讀的面板；技能頻繁呼叫大型底部對話，會長時間遮住戰場。
- 既有瀏覽器 smoke 可以在 Boss draw count 為 0 時通過，因此不能作為完整戰鬥品質證明。

## 4. 三秒測試與玩家面問題

玩家進入戰鬥三秒內應回答：我方是誰、敵人是誰、打到哪一波、誰正在受傷、我能做什麼。現況主要失敗點依優先順序為：

1. 角色太小且重疊，武器、傷害字、VFX 與血條堆在同一區域。
2. 敵人、敵將與 Boss 外觀無法穩定對應身份，攻擊與死亡又會改變或破壞輪廓。
3. 大型技能對話、預告、HUD、右側功能列與底欄同時占據戰鬥面積。
4. 資源數字被截斷，關卡只剩編號；歷史章名、關卡名與實際敵人缺乏一致敘事。
5. 玩家離開戰鬥去看武將或編隊時，面板可能被自動推關關閉，破壞基本操作信任。

## 5. 系統調整決策

| 領域 | 保留 | 調整 | 重製／替換 | 暫緩或隱藏 |
|---|---|---|---|---|
| 核心循環 | 直式、自動戰鬥、離線收益、非抽卡 | 讓每關前後都有一次清楚配置選擇 | 失敗原因與剋制提示 | — |
| 戰鬥 | 五人小隊、波次、Boss、Canvas | 單一狀態機與固定畫層 | attack／hit／death、兵器 socket、敵人與 Boss 資產 | 未通過 gate 的角色與攻擊圖 |
| 編隊 | 3×3 棋盤、最多五人 | 支援點選／拖曳換位、前後排與 lane 說明 | 用真實戰鬥結果驗證站位價值 | 自動推薦等延伸功能 |
| 戰法 | 三種既有方向 | 每場只攜帶一個，顯示適用情境與戰果差異 | 戰法回饋與技能視覺 | 多套預設、複雜天賦樹 |
| 裝備 | 武器／防具／飾品槽位 | 建立擁有、掉落、比較與換裝 | 戰場兵器使用角色／方向 socket 或含兵器動畫 | 66 件同時對玩家開放 |
| 關卡 | 20 章／100 關資料骨架 | 先完成第一章 10 關的敵人、節奏與獎勵 | 章節／關卡命名、精英與 Boss 機制 | 後 19 章對外宣稱完整 |
| HUD／面板 | 390×720 基準、底部主要導覽 | 戰鬥只保留生命、波次、速度與必要操作 | 小型技能喊話、面板層級、英雄詳情 | 戰鬥中的資源總覽與多重中央 overlay |
| 副模式 | 系統入口與資料可保留 | 只選一個模式重用正式戰鬥 | 獎勵與失敗回饋 | 排名、活動、塔、戰令、IAP 先隱藏，直到有完整玩法或正式服務 |
| 營運／平台 | 本地訪客、PWA／Capacitor 架構 | 誠實顯示未設定功能 | 正式登入、廣告、IAP 依發布條件另案完成 | 不以 placeholder 冒充可用服務 |

## 6. 下一個可玩版本：第一章垂直切片

### 範圍

- 1 個完整章節、10 關；每關有一致的地名、敵方陣容、難度目的與獎勵。
- 8 名經核准的可玩武將；角色名單須覆蓋前排、突擊、遠程、謀士與輔助，但未完成者不出現在玩家可用清單。
- 3 種普通敵人、1 種精英、2 名有唯一剪影／兵器／技能的 Boss。
- 每個出戰單位完成 idle、move／entry、anticipation、contact、recovery、hit、death、removed。
- 玩家可編輯 3×3 位置、選擇 1 個戰法、從已擁有的小型裝備池換裝。
- 1 個副模式使用與主線相同的真實戰鬥規則；其餘入口暫隱藏或清楚標示未開放。
- 開局、教學、首敗、首勝、成長、重試、下一關、離線返回形成一條不被面板或自動推關打斷的流程。

### 明確不做

- 不在此切片擴增第 9 名以上武將、後續章節、排行榜、多人、正式 IAP、戰令或第二個活動模式。
- 不以更多數值、粒子、震動或裝飾遮掩 body、兵器、狀態機和介面層級問題。
- 不允許程序方塊、線段人體、通用武器漂浮、未核准 alias 或 inventory 圖直接進戰場。

## 7. 製作階段與依賴

### Phase 0 — 品質凍結與縮編

- 鎖定垂直切片角色、敵人、武器、關卡與面板範圍。
- 對未完成系統採取隱藏、停用或明確未開放，不再用入口數量代表完成度。
- 建立角色／敵人／Boss → body／weapon／skill／VFX 的單一資產表。

完成條件：任何會出現在切片的內容都有 owner、資產契約、驗收案例；範圍外內容不干擾流程。

### Phase 1 — 戰鬥視覺與生命週期重製

- 先製作中立站姿與腳底 anchor，再製作方向、五階段攻擊、受擊與死亡。
- 武器採逐角色、逐方向 socket；若攻擊圖已含武器，外部武器不得再畫。
- 普通敵人按兵種建立不同剪影；Boss 使用唯一 body、兵器與至少一個可讀招式。
- 技能特效遵循蓄力 → 接觸 → 消散，不蓋住身份與命中點；移除全畫面 shake。

完成條件：資產 gate 通過，8 名英雄、3 種敵人、1 精英、2 Boss 的全狀態矩陣無錯圖、黑框、雙身體、漂浮兵器或死亡殘留。

### Phase 2 — 核心決策重製

- 編隊可實際換位，並在 UI 顯示前排承傷、後排安全與 lane 加成。
- 戰法改為每場攜帶一個；關卡預覽提供足以做選擇的敵方情報。
- 裝備由「免費輪換所有資料」改為「已擁有清單、比較、掉落與有限升級」。
- 用固定種子戰鬥驗證：至少兩種配置會產生可解釋、可重現的戰果差異。

完成條件：玩家敗北後能在 30 秒內理解一個可採取的調整，且調整確實改變模擬結果。

### Phase 3 — UI、導覽與資訊層級重製

- 戰鬥 HUD 僅保留角色／敵方狀態、波次／Boss、速度與一個主操作層；資源移到非戰鬥頁。
- 大型技能對話改成靠近角色的小型喊話；中央一次只允許一個 Boss／波次／結算 overlay。
- 面板開啟時，自動戰鬥可依產品決策繼續或暫停，但不得自行關閉、搶焦點或重設捲動位置。
- 重做武將列表、英雄詳情、戰法、日常與商城的資訊密度；先顯示可用項，鎖定內容分段呈現。
- 清除命令紙張的跨面板對角線、英文內部標籤、`undefined`、文字截斷與繁簡／錯字。

完成條件：320×568、390×720、430×932 的三秒測試與主要面板截圖通過；鍵盤焦點、返回與 reduced motion 有證據。

### Phase 4 — 第一章內容、成長與經濟

- 每關定義敵人組合、教學目的、預估時長、首勝／重複獎勵與失敗提示。
- 重新校準金幣、糧草、玉璧、碎片與體力的來源／消耗；通用碎片只作保底材料，不抹平角色身份。
- 商店建立可重複但有限的消耗點；按鈕文案反映購買、兌換或領取的真實行為。
- 副模式必須進入正式戰鬥，不再只比較總戰力後立即給結果。

完成條件：空帳號可連續玩完第一章；無卡死、無資源負數、無重複發獎，成長節奏與失敗點有測試記錄。

### Phase 5 — QA、效能與逐批擴張

- 自動測試至少覆蓋一次完整勝利、一次完整失敗、Boss draw、死亡／移除、結算與面板保持。
- source 與 `www` 分別做固定尺寸截圖／錄影；Android 實機再驗證 WebView、觸控、背景、音訊與登入 fallback。
- 量測低階裝置 frame time、Canvas draw count、資產解碼、記憶體與長時間 idle。
- 只有前一批角色與關卡通過相同 gate，才能以批次擴張；每批不超過可完整驗收的範圍。

完成條件：QA 矩陣全過、console 乾淨、人工美術驗收簽核，才可把目前判定改為 `PASS`。

## 8. 各職能不可省略的驗收

### 企劃

- 每個可見系統都回答：玩家做什麼選擇、為何現在做、結果如何回饋、失敗後如何修正。
- 關卡不是單純 HP／ATK 等比增加；精英與 Boss 至少有一個改變配置判斷的規則。
- 系統入口沒有真實玩法或獎勵循環時，寧可隱藏，不以「敬請期待」塞滿首頁。

### 美術與動效

- **保留**：低彩度三國戰場、像素角色方向、紙張／金屬材質語彙。
- **調整**：比例、剪影、陣營色、地面接觸、VFX 明度與 HUD 對比。
- **替換**：稀疏攻擊圖、錯誤敵將 alias、通用 Boss 放大、斷裂兵器、方塊 fallback。
- 攻擊節奏須有 anticipation、contact 與 recovery；受擊短促，死亡完整收束到 removed。

### 工程

- 資料、模擬狀態、渲染與 UI 不再各自推導平行戰鬥狀態。
- 移除重複 renderer 函式與累積 override；將戰鬥 HUD、命令面板與共用 token 分層，避免持續在 `styles.css` 尾端覆寫。
- 面板生命週期與關卡生命週期解耦；存檔 migration、獎勵 idempotency、資產缺失採明確錯誤。

### QA

- 「smoke PASS」只代表基本循環有跑；未取得 Boss、攻擊、死亡、結算與固定尺寸畫面證據，不得宣告戰鬥完成。
- 視覺硬錯誤、錯圖、遮擋、黑框、方塊、武器漂浮、雙身體與死亡殘留任一存在即 `FAIL`。
- 每次關閉問題必須附版本、尺寸、關卡、編隊、重現步驟與截圖／影片；不能只以程式碼已修改為證據。

## 9. 主要風險

| 風險 | 影響 | 控制方式 |
|---|---|---|
| 同時維護 50 名武將 | 資產與技能品質持續稀釋 | 先鎖 8 名，通過後小批擴張 |
| 先改 UI 再改戰鬥契約 | 新介面仍包住錯誤資產與狀態 | Phase 1 與 Phase 2 先定資料／狀態契約 |
| 用戰力數字代替玩法 | 副模式看似很多但沒有決策 | 只保留一個重用真實戰鬥的副模式 |
| 自動測試過度樂觀 | 錯圖與遮擋再次漏過 | 對 Boss、death、settlement、截圖建立硬斷言 |
| source／`www` 不同步 | 驗收與實際 build 不一致 | 兩個 target 分開啟動、分開保存證據 |
| 正式服務尚未設定 | 登入、廣告、IAP 無法驗證 | 保持誠實 fallback，列為外部 release gate |

## 10. 完成定義

下一個可玩版本只有在以下條件全部成立才算完成：

1. 第一章 10 關可由空帳號玩完，勝、敗、重試、下一關、重載與離線返回均正確。
2. 切片內角色、敵人、Boss 與兵器的身份和全生命週期通過自動與人工驗收。
3. 編隊位置、戰法與裝備各有一個可觀察、可解釋的戰術選擇。
4. 所有基準尺寸無遮擋、截斷、對角線、`undefined`、錯字、搶焦點或面板被自動關閉。
5. `npm run test:combat-assets`、完整瀏覽器流程、QA 測試矩陣與 Android 實機核心案例通過。
6. 範圍外系統不冒充完成；正式登入、廣告、IAP 與發布條件仍依外部 gate 判定。
