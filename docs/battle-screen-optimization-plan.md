# 戰鬥畫面全面審視與優化方案

狀態：已記錄規劃。作為戰鬥場景、HUD 配置、視覺層級與戰鬥回饋的後續實作指南。

---

## 1. 審視總結與評分

根據遊戲截圖與現有程式碼（`index.html`、`styles.css`、`js/game/`），目前古戰場像素風格鮮明、武將與坐騎辨識度佳，但 **HUD 資訊密度過高、層級競爭嚴重**。戰場被上方頂部資訊、下方導航、右側快捷欄與左側波次預覽四面包圍，導致核心戰鬥區域（Gameplay Area）受壓迫。

| 維度 | 分數 | 現況分析 |
|---|---|---|
| **Clarity** | 5/10 | 資訊區過多、層級平坦，波次與敵將預覽互相競爭 |
| **Hierarchy** | 4/10 | 戰場被四面 HUD 壓縮，Level 3/4 裝飾與功能搶走 Level 1 焦點 |
| **Game Feel** | 6/10 | 像素角色與天氣地形佳，但缺少波次轉場與強烈打擊回饋 |
| **Touch UX** | 5/10 | 右側快捷按鈕密集（11 顆）、資源列數字字級偏小 |
| **Consistency** | 7/10 | 「戰場鐵木」表面家族與像素材質維持一致 |
| **Polish** | 5/10 | 傷害飄字堆疊、掉落物辨識度低、戰鬥節奏感可再提升 |

## 2. 核心問題與優化清單（Top 10）

### 【P1】重大結構與層級問題

#### [P1-1] 右側快捷欄過度佔用戰場空間
- **位置**：`.right-rail`（`styles.css`、`index.html`）
- **現象**：11 個圓形按鈕垂直排列，佔據畫面右側 ~55px 寬度，遮擋敵軍生成與右路戰鬥。
- **方案**：
  1. 精簡常駐按鈕為 3~4 個高頻項（如：設定、軍件、日務、行商）。
  2. 其餘功能收入「更多（☰）」收合選單，點擊後展開抽屜。
- **驗收**：右側遮擋寬度 ≤ 30px，戰場水平可視寬度提升。

#### [P1-2] 戰鬥信息區（波次 + 敵將預覽）層級混亂
- **位置**：`.battle-info-lane`、`.enemy-preview`
- **現象**：波次標籤、敵軍數與敵將預覽卡片常駐於左上方，與主公卡形成資訊重疊。
- **方案**：
  1. 波次資訊精簡為 `第 1 波 · 敵 8` 整合至頂部資訊列。
  2. 敵將預覽卡片改為**波次開始時出現 2 秒後自動淡出**，不常駐遮擋畫面。
- **驗收**：左上方不再常駐大型卡片，波次進度一目了然。

#### [P1-3] 頂部 HUD 資訊過載
- **位置**：`.top-hud`、`.lord-card`、`.battle-meta`
- **現象**：主公頭像、等級、經驗條、稱號、自動/速度按鈕、章節、關卡名與戰力全部並列，高度達 75px。
- **方案**：
  1. 主公卡在戰鬥中僅保留頭像與等級（隱藏常駐經驗條，點擊展開詳情）。
  2. 關卡資訊濃縮為單行標籤（如：`桃園結義 2-2`）。
  3. 頂部 HUD 高度壓縮至 ≤ 55px。
- **驗收**：上方敵軍生成區（Y=200）完全露空不被覆蓋。

#### [P1-4] 戰場可視區域壓縮
- **位置**：Canvas 座標佈局與整體佈局（390×720）
- **現象**：上下左右 HUD 包夾，實際淨戰場高度僅約 480px。
- **方案**：
  1. 實施 P1-1 至 P1-3 瘦身後，戰場淨高度提升至 540px 以上。
  2. 戰場在整體視圖佔比達 65% 以上。

### 【P2】視覺可讀性與戰鬥體驗問題

#### [P2-5] 波次轉場缺乏節奏感
- **位置**：`game-combat.js` 波次推進邏輯
- **現象**：波次更換時瞬時刷新單位，缺少轉場過渡。
- **方案**：
  1. 波次切換時加入 150ms 畫面微暗/波次文字彈跳提示。
  2. 新波次敵軍自上方平滑滑入戰場。
- **驗收**：每波清空到新波開始有明確節奏停頓與推進感。

#### [P2-6] 血條與能量條可讀性不足
- **位置**：`game-render.js`（`drawHealthBar`、`drawSkillEnergyBar`）
- **現象**：血條高 4px、能量條高 3px，在行動裝置上掃讀困難。
- **方案**：
  1. 我方與 BOSS 血條高度提升至 5px，寬度提升至 40px，加深邊框對比。
  2. 技能能量條提升至 4px，滿能量時強化金色脈衝。
- **驗收**：在 390px 寬度下能即時掃讀陣容健康與技能充能狀態。

#### [P2-7] 傷害數字密集堆疊
- **位置**：`game-render.js`（`drawEffects` 飄字邏輯）
- **現象**：多人同擊時傷害數字垂直重疊，無法辨識數值。
- **方案**：
  1. 傷害飄字加入 ±15px 水平隨機散射與輕微角度偏轉。
  2. 暴擊數字（CRIT）加大彈跳振幅與更清晰的字重外框。
- **驗收**：3 個以上單位同時受擊時，數字依然可獨立辨識。

#### [P2-8] 資源掉落物辨識度低
- **位置**：`game-render.js`（`drawResourceDrops`）
- **現象**：掉落圖素僅 14×11px，文字 8px，缺乏獲得感。
- **方案**：
  1. 掉落物尺寸放大 25%（18×14px）。
  2. 「+數值」字體升至 12px 並加粗深色描邊。
  3. 拾取時加入向底部資源列飛入的動效引導。
- **驗收**：掉落類型（金/糧/玉/碎）一眼可分。

#### [P2-9] 底部資源列數字偏小
- **位置**：`.resource-strip`
- **現象**：4 種資源與 BOSS 按鈕擠在單行，數值 11px 不易閱讀。
- **方案**：
  1. 數字字級提升至 13px，間距緊湊化。
  2. BOSS 挑戰按鈕在可挑戰狀態時加入脈衝光效。

### 【P3】細節拋光問題

#### [P3-10] 戰場背景水印文字干擾
- **位置**：`game-render.js`（`drawBattleTitle`）
- **現象**：關卡大字（43~54px）印在中央（Y=326），與角色重疊。
- **方案**：
  1. 不透明度（alpha）由 0.17 降至 0.10。
  2. 位置上移至 Y=260，避開我方交戰熱區。
- **驗收**：水印不干擾角色輪廓與戰鬥技能特效。

## 3. 保留與傳承（Keep）

1. **武將多層像素辨識**：頭部飾物、甲冑紋理、專屬兵器分層繪製（`drawHeroDetails`）。
2. **天候與環境系統**：雨、雪、夜戰與章節地表配色演繹。
3. **BOSS 登場 Banner**：強敵來襲儀式感與橫幅進出場動畫。
4. **戰場鐵木材質**：深綠灰、木褐與米金的經典三國放置風格。
