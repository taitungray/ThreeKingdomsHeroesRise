# 三國：群英再起 — 戰鬥角色改用點陣圖片 (Sprites) 專題評估方案

> **ARCHIVED EVALUATION — 2026-08-27。** 尺寸與完成聲明可能已被後續實作取代；現行契約見 [戰鬥角色渲染契約](../../standards/combat-character-render-contract.md)。

> 本文件專門回答：**「戰鬥中的像素小人如果全部改成圖片，到底行不行？怎麼做最好？」**

---

## 一、核心結論：戰鬥角色改成圖片會帶來質的飛躍！

### 為什麼戰鬥角色更應該改成圖片？

1. **徹底解決「大眾臉」問題**：
   - 目前只有 12 個人在代碼裡有手繪特徵，其餘 38 名武將在場上全是「換色大眾臉」。
   - 改用圖片後，**每名武將一張專屬 48×48 像素圖**，趙雲銀甲白袍、魏延反骨面具、姜維綠袍金冠、張角黃巾符印全部一目了然！
2. **細節與質感提升 3~5 倍**：
   - 程式畫不出精緻的飄動雉雞翎、關羽美髯公的鬍鬚紋理、龍膽槍上的銀光閃爍。
   - 圖片可以用專業像素工具（Aseprite）做出高水準的 **3~4 階光影與高光點**。
3. **代碼大幅瘦身，不再發熱**：
   - 目前 `game-render.js` 為了手繪角色幾何方塊，寫了超過 **1,000 行** 繁瑣的 `drawPixelRect(-8, -39, 5, 2, '#271b15')`。
   - 改用圖片後，只需一行 `ctx.drawImage(heroSprite, x, y)`，執行效能大幅提升，手機更省電。

---

## 二、兩大改造方案抉擇（選哪種最好？）

### 方案 A：分層拆件式像素素材（Modular Layered Sprites）— **【強烈推薦 ⭐⭐⭐⭐⭐】**

> **原理**：保留現有的「紙娃娃系統」，但把每個代碼方塊換成精緻的透明 PNG 零件。

```
[頂層] 武器圖 (Weapon PNG) ── 隨攻擊動作旋轉傾斜
  │
[中層] 武將本體圖 (Hero Head & Body PNG) ── 呼吸起伏
  │
[底層] 坐騎圖 (Mount PNG) / 戰靴 ── 跑步奔馳
```

*   **優點**：
    *   **完美保留「自由換裝」**：關羽可以隨便換騎「赤兔馬」或「玉獅子」，也能換拿「丈八蛇矛」或「方天畫戟」。
    *   **產能極省**：50 名武將只需 50 張本體圖 + 8 張武器圖 + 7 張坐騎圖，就能組合成數千種戰鬥外觀！
    *   **工作量小**：只需改寫 `game-render.js` 的 `drawUnit` 函數，戰鬥邏輯（移動、受擊、碰撞）完全不用動。

---

### 方案 B：整隻手繪逐幀點陣動畫（Full Frame-by-Frame Spritesheet）

> **原理**：每名武將是一張完整的精靈圖集（包含：待機 4 幀、奔跑 6 幀、揮砍 4 幀、死亡 2 幀）。

*   **優點**：動作極度流暢生動，像經典街機《吞食天地》或《三國戰紀》。
*   **致命缺點**：
    *   **紙娃娃換裝失效**：因為武器和坐騎畫死在角色身上，如果要換坐騎或換武器，每個人必須畫幾十套動畫，產能無法承受。
    *   **新增武將成本極高**。

## 三、推薦落地方案：方案 A（拆件式精緻像素）技術規範

### 1. 規格尺寸定義（Canvas 統一規格）
*   **武將本體 (Hero Body)**：`32×38` 像素（透明背景 PNG），錨點設於腳底中心 (16, 38)。
*   **神兵武器 (Weapons)**：`16×32` 像素，錨點設於手柄握把處。
*   **神獸坐騎 (Mounts)**：`48×32` 像素，錨點設於馬背鞍座中心。
*   **敵方 Boss (Boss Sprites)**：`48×56` 像素（張角/董卓/呂布等獨立專屬大圖）。

### 2. 渲染流程改寫對比

**改造前（繁瑣易錯的代碼方塊）**：
```javascript
// 以前需要幾百行代碼畫關羽
drawPixelRect(-8, -39, 5, 2, '#271b15');
drawPixelRect(-2, -49, 4, 3, '#e0c36d');
drawPixelRect(-12, -27, 4, 10, "#d5d9d2");
// ... 下略 80 行
```

**改造後（極簡優雅的 GPU 圖片渲染）**：
```javascript
function drawUnit(unit) {
  ctx.save();
  ctx.translate(unit.renderX, unit.renderY);
  ctx.scale(unit.scale * unit.facing, unit.scale);

  // 1. 畫坐騎
  if (unit.loadout?.mount && unit.loadout.mount !== 'foot') {
    ctx.drawImage(ASSETS.mounts[unit.loadout.mount], -24, -20);
  }
  // 2. 畫武將本體 (精緻手繪像素圖)
  ctx.drawImage(ASSETS.heroes[unit.hero.id], -16, -34);

  // 3. 畫武器 (隨攻擊角度旋轉)
  ctx.save();
  ctx.translate(6, -18);
  ctx.rotate(unit.weaponSwing);
  ctx.drawImage(ASSETS.weapons[unit.loadout.weapon], -4, -28);
  ctx.restore();

  ctx.restore();
}
```

## 四、改造成效對比總結

| 評估項目 | 現有代碼手繪角色 | 改成圖片拆件素材 (方案 A) |
|---|---|---|
| **武將獨立外觀** | 僅 12 人有特徵，其餘 38 人共用 | **50 名武將 100% 擁有獨立精緻造型** |
| **名將 Boss 震撼度** | 只是放大版小兵 | **張角道袍符文、董卓巨劍重甲、呂布翎羽霸氣登場** |
| **渲染效能 / 發熱** | 每幀計算數百幾何矩形，CPU 發熱 | **GPU 紋理快取加速，每幀 < 0.1ms** |
| **代碼檔案大小** | `game-render.js` 52KB (1343 行) | **精簡至 ~15KB (300 行以內)** |
| **美術升級與替換** | 需懂 JS 代碼並手動調座標 | **美術直接出 PNG 覆蓋即可，無需改代碼** |


## 實際落地結果補充（2026-08-27）

- 方案 A 已接入：body、武器與坐騎以拆件合成，Boss 使用獨立大圖，全部使用 nearest-neighbor 與 foot-center anchor。
- `game-render.js` 的 `drawUnit` 已改由 `TaoyuanAssets` 管理圖片載入、快取與 fallback，同一套渲染尺寸適用於不同角色。
- 50 名武將皆已有 combat body path，圖片核心渲染與程式降級可同時運作。
## 實作補充：攻擊不使用單張靜態圖（2026-08-27）

戰鬥角色的本體 PNG 保留作為身份與服裝層；攻擊演出由 Canvas 逐幀驅動，依 8 方向套用身體位移、蓄力／出招／收招姿勢、手臂與武器掃掠。遠程角色另有弓弦拉伸，謀士技能另有手部法術環，並保留既有坐騎、裝備與 VFX 疊加。
