# 三國：群英再起 UI、文字與互動規範

狀態：強制的產品底線。這份文件是本專案的 UI source of truth；新增畫面、面板、按鈕或動畫前先套用與本次改動直接相關的條目。

## 1. 視覺方向

一句話：**古戰場像素軍帳，使用朱砂、鐵灰、木褐與米金打造有重量的三國放置 RPG。**

三個視覺支柱：

1. 戰場先於介面：玩家第一眼看到敵軍、武將與危險狀態。
2. 材質先於卡片：木、鐵、紙卷、金線可被感覺到，不做 SaaS dashboard。
3. 角色先於換色：武將要靠頭冠、鬍鬚、甲冑、兵器、待機與技能特效辨識。

禁止把所有內容做成同一種圓角卡片、玻璃透明、藍紫漸層或 emoji 圖示列。若使用 CSS 暫代材質，必須列入後續素材替換清單。

### 1.1 可執行 Design Tokens

以下是 UI 的唯一實作基線；新增畫面不得在元件內任意新增色票、字型或字級。若確實需要新值，先更新本節，再修改 CSS。

| 類別 | Token／固定值 | 用途 |
|---|---|---|
| 深色底 | `--ui-ink: #101613` | 遊戲殼、鐵木、主要陰影 |
| 紙卷底 | `--ui-paper: #ead8aa`、`--ui-paper-light: #f8edcf` | 面板、卡片、說明區 |
| 金線 | `--ui-bronze: #8b6a3c`、`--ui-bronze-light: #d9b86d` | 外框、分隔線、稀有提示 |
| 朱砂 | `--ui-cinnabar: #a84232`、`--ui-cinnabar-dark: #63231d` | 主要 CTA、危險、首領 |
| 暗玉 | `--ui-jade: #6d9976` | 成功、已裝備、完成狀態 |
| 正文 | `--panel-ink: #2a2117`、`--ui-muted: #6f614a` | 紙卷上的主文與輔助文 |
| 反白 | `#fff6d0` | 朱砂／鐵木按鈕文字；禁止用深棕字壓在深紅底 |
| 字型 | `Huninn Game` | DOM、按鈕、HUD、Canvas 文字唯一主字型；系統字型只作 fallback |
| 字級 | 標題 `21px`、段標 `16px`、正文 `15px`、按鈕 `16px`、輔助 `14px` | 角色以層級區分，不靠任意放大 |
| 間距 | `4 / 8 / 12 / 16 / 24px` | 元件內距、卡片間距、區塊間距 |
| 觸控 | 最小 `44×44px` | 所有主要按鈕、圖示按鈕、導覽項 |

手機版面固定以 `390×720` 為 authored viewport；`430px` 是可容納安全邊距的外部寬度，不得把遊戲殼或面板拉成桌面工作區。手機橫向與觸控平板同樣維持直式殼；桌面預覽也只作固定直式的 letterbox，不改變手機元件比例。

## 2. 表面家族

同一個列表或面板只能選一個主要表面家族，不可黑白混成網頁表格。

| 家族 | 用途 | 底材 | 文字 |
|---|---|---|---|
| 戰場鐵木 | 戰鬥 HUD、波次、資源列、底欄 | 深綠灰、鐵黑、木褐 | 米金、暖白、朱砂 |
| 軍帳紙卷 | 武將詳情、紙娃娃、說明、設定 | 米紙、灰褐、內框金線 | 深棕、墨黑 |
| 朱砂戰令 | 主要 CTA、首領、危險、確認 | 朱紅、深褐、金邊 | 米金、暖白 |
| 深色金線 | 戰報、排行、成就、獎勵狀態 | 深褐至黑褐漸層 | 淡金、暖白、成功綠 |

必要資訊不能只靠顏色；selected、disabled、claimed、locked 都要有文字、圖形或位置差異。

## 3. 視覺層級與三秒測試

每一個畫面必須讓玩家在三秒內回答：

- 我現在在戰鬥、武將、編隊還是設定？
- 下一個最重要的操作是什麼？
- 哪個敵人或獎勵最值得注意？
- 目前是可操作、危險、載入中、已完成還是已領取？

戰鬥畫面層級固定為：

1. 戰場與武將動作
2. 敵軍、首領與危險
3. 主要操作（自動、速度、首領挑戰）
4. 波次與關卡狀態
5. 資源與底部導覽
6. 排行、設定等 meta 功能

HUD 不得遮住敵軍生成區、主要戰鬥單位或底部操作。

## 4. 字體與文案

- 介面固定使用繁體中文；專有名詞維持三國語氣，避免突然出現 SaaS 用語。
- 正文與必要說明至少 14px；主要按鈕與重要數值至少 16px。
- 小於 12px 只能用於非必要角標，不得承載費用、解鎖條件、錯誤原因或獎勵。
- 重要按鈕使用單行文案；費用放在同一個按鈕內，例如「升級（70 銅錢）」。
- 不重複顯示同一資訊；獎勵圖示與可見幣種名稱二擇一，完整名稱保留在 aria-label 或 title。
- 數字使用等寬數字或固定寬度欄位，避免資源列與戰鬥飄字跳動。
- 字型唯一來源為專案內建 `Huninn Game`（jf open 粉圓 2.1，OFL-1.1）；HUD、面板、按鈕、結算與 Canvas 戰鬥文字都使用同一字模，系統字型只作載入失敗 fallback，禁止再直接指定 `DFKai-SB`／`KaiTi` 或依裝置替換字模。
- 字體角色以尺寸、字距、顏色與位置區分：展示標題加大並放寬字距，正文維持緊湊，數字啟用 `tabular-nums`／`lining-nums`；資料文字不得套多重模糊陰影，文字陰影最多一層 1px 實色邊。
- 長字串先保留獨立欄位與最小寬度，再以單行省略；不得讓關卡名、主線提示、角色名稱或按鈕文字跨欄覆蓋。

## 5. 行動觸控與響應式

- 所有可點擊的主要按鈕、圖示按鈕、導覽項最小 44×44 CSS px。
- 不依賴 hover；pressed、selected、disabled 必須在觸控上也可辨識。
- 互動區不能貼到劉海、手勢列或螢幕邊緣；使用 safe-top、safe-bottom。
- 直式基準尺寸是 390×720；430px 以上只增加外側安全留白，不展開遊戲殼；超窄、高螢幕、橫向都要有降級策略。
- 戰場 canvas 使用像素化渲染與固定內部座標，不用 CSS 拉伸角色比例。
- 不用負 margin、絕對定位或 z-index 硬蓋來解決不確定的溢位；先修 layout anchor。
- 短螢幕優先縮減裝飾與次要資訊，不縮小主要按鈕到不可按。
- 武將詳情是養成頁：升級主 CTA 必須釘在面板底列，打開當下看得見，不要求先滑過列傳。神兵真名與精煉共鳴併入裝備列，緣分用 chip 不重複陣容長文，列傳預設摺疊。
- 命令面板共用單一內容捲動容器；切換面板必須回到面板標題，不得沿用上一頁的 scrollTop 或以平滑捲動把標題／操作列帶出視窗。
- 遊戲介面不是可選取的文件：根節點與內容禁止滑鼠拖曳反白（`user-select: none`，`selectstart` 文件級攔截）；`input`／`textarea`／`select`／`[contenteditable="true"]` 保留文字輸入例外。
- 禁止瀏覽器原生拖出或保存遊戲圖片：`img`／`svg`／`picture`／`canvas`／連結的 `dragstart` 與遊戲根節點 `contextmenu` 必須攔截；遊戲內按鈕仍由 pointer／click 正常操作。

## 6. 元件狀態

每個互動元件至少定義：

- normal
- hover（桌面才需要）
- pressed
- selected
- disabled
- loading
- error
- completed 或 claimed（若有領取流程）

disabled 不能只用 opacity；要有實色、文字原因與不可操作的語意。若原因不明顯，aria-label 必須說明原因。

## 7. 動畫與回饋

- pressed 使用短促的位移或 scale 0.97～0.99，不做長時間浮動。
- 面板進出、toast、獎勵揭示使用短轉場；不要讓所有卡片同時 stagger。
- 成功、拒絕、載入中、首領出現要有不同的視覺語彙與音效。
- selected、expanded、pressed、disabled 同步 aria 狀態。
- 裝飾圖使用 aria-hidden；資訊圖示由父容器或 aria-label 提供完整語意。
- 對比度、文字大小與觸控規範以 accessibility-wcag.md 為準。

## 10. 禁止廉價網頁遊戲感

驗收一句話：**玩家要覺得在玩三國手遊，不能一眼看出這是網頁。** 通過 Web 技術實作，但表面必須是原生直式手遊。

不合格（任一即退回）：

- 工具列／書籤列：兩排以上同造型小圓鈕、8–11px 標籤、漢堡選單再疊一排 icon
- 網頁卡片：每區都是同一種圓角 card、細 1px 邊、玻璃透明、dashboard 留白
- 網頁字級：關卡名被截成半行、資源數字小於 14px、底欄小於 14px
- CSS 佔位感：clip-path 隨便切一塊當按鈕、英文 eyebrow、Times New Roman、VS／LOCAL／DAILY 當裝飾
- 介面搶戰場：HUD 四面夾擊，武將比按鈕還小

合格底線：

- HUD 是軍帳物件：鐵條、木牌、朱砂印、金線內框，有厚度與投影，不像 HTML 按鈕列
- 頂欄主公牌點一次開啟主公軍府；經驗分數疊在經驗條上單行，不得與 Lv 或稱號疊字
- 右側常駐最多 4 個快捷＋「更多」；更多必須是軍務清單（15px 列高 44px），禁止第二排迷你 icon
- 頂欄通寬指揮條，關卡與波次完整可讀，不截成 48px
- 底欄是指揮甲板：資源槽＋朱砂首領印＋五個雕刻頁籤
- 面板是紙卷軍帳，不是白底表單

## 11. 不可直接套用的做法

- 不直接複製 IncenseAshes 的畫面、神明素材、顏色或頁面骨架。
- 不因「看起來像遊戲」而新增 emoji chrome、重複 icon＋文字、無意義的紅點或常駐 toast。
- 不把未完成功能偽裝成可領獎、已同步或已儲存。
- 不在未定義 UI Contract 前大量堆 CSS。

## 12. UI 驗收

- 390×720 直式：主 CTA、底欄、資源與紙娃娃均可操作且不裁切。
- 430×932 高螢幕：上方 safe area 與底部手勢區不遮內容。
- 320px 以下：文字不重疊，非必要裝飾可隱藏。
- 橫向短高：顯示旋轉提示，不讓戰鬥 UI 半截露出。
- 檢查 normal、pressed、selected、disabled、claimed、loading、error。
- 檢查無障礙名稱、焦點、對比與 reduced-motion。

## 13. 戰鬥角色、敵人與兵器

戰鬥畫面以「剪影可辨識、透明背景、腳底定位、兵器握在手上」為底線。黑框、方塊、錯圖、雙身體、雙兵器、漂浮、穿模與死亡殘留一律不合格。

資產尺寸、錨點、圖層、fallback 與生命週期只由 [戰鬥角色渲染契約](combat-character-render-contract.md) 定義；本文件不重複維護第二份數值。

## 14. 戰鬥狀態與生命週期

戰鬥 action 是 idle／move／attack／hit／death／removed 的唯一來源；CSS、Canvas 與 timer 不得各自猜測狀態。角色渲染或資產改動後，依 [QA 測試矩陣](../qa/qa-test-matrix.md) 與 [視覺驗收規範](../qa/visual-qa.md) 回歸。

## 15. 敘事覆蓋層預算

- 同一時刻最多一個中央覆蓋層：波次標題、首領橫幅、角色對話、全畫面教學、結算只能依序出現。
- 敵將預告固定在頂部資訊 lane，顯示不超過 2 秒、不可攔截觸控、不得覆蓋生成區或角色頭頂。
- 首領出場使用短橫幅；橫幅期間不再疊角色對話。需要台詞時，等橫幅完全退場後再顯示於底部安全區。
- 戰鬥進行中不可用寬幅深色卡片長駐中央；重要訊息優先縮成 HUD chip 或戰報。
- 結算開啟前清除敵將預告、對話、首領橫幅與教學焦點，避免 z-index 穿透。

## 16. 小尺寸戰鬥可讀性

- 小尺寸角色優先保留粗像素剪影，再使用肩甲、領口、腰帶、臉部高光、髮冠與一個裝備標記補細節。
- 血條、能量條與影子跟隨 foot anchor；平滑移動不能模糊角色像素。
- 我方單位血條在上、技能氣條在下，分兩列繪製；禁止把血／氣併成同一條紅藍雙色，也禁止兩條佔同一 Y。
- 普通傷害字與暴擊字必須在 390px 戰場上可讀，但不得疊成遮住角色的文字牆。
- 實際縮放值屬 renderer 現況，記在 `specs/` 或程式，不在 UI 規範硬寫可能過時的數字。

## 17. 關卡、敵將與頭像身分

- 關卡名稱由資料驅動，在 HUD 與必要戰場標記使用同一來源，不回退成無身分的泛用文字。
- 敵將預告、波次資料與實際敵人資產必須指向同一 general ID；Boss 波切換為該 Boss 身分。
- 頭像使用剪影、臉部標記、服裝色塊三個固定身分錨點；詳情、縮圖、對話與敵將預告都要保留。
- 裝備層不得蓋掉角色核心身分，陣營底色或 accent rune 只能輔助辨識。

## 18. 戰鬥介面重整契約（2026-08-30）

本節是本輪依 `C:/IncenseAshes/` 的「先定義層級、再落地元件、最後做固定尺寸驗收」方法調整後的本專案契約；只借鑑流程，不複製參考案的題材、素材、顏色或頁面骨架。

### 18.1 Screen Goal 與層級

- 戰鬥：在三秒內看懂「我方／敵方、當前關卡／波次、下一個操作」，戰場永遠高於裝飾。
- 日常軍務：先看今日可完成任務，再看進度、獎勵與領取狀態；簽到固定在任務清單後方。
- 視覺方向：**鐵木軍帳・朱砂軍令**；三個支柱為威嚴、可讀、戰場優先。
- 戰鬥 HUD 層級固定為：戰場 → 威脅／首領 → 速度與主線操作 → 波次／關卡 → 資源 → 導覽與 meta。

### 18.2 Layout Map 與 anchor

直式基準為 390×720，所有座標都是版面區域而非互相覆蓋的 z-index 修補：

| 區域 | anchor／尺寸 | 規則 |
|---|---|---|
| 頂部指揮條 | safe-top 起算；主公＋速度一列，關卡／波次第二列 | 關卡文字不與主公牌或速度鈕共用同一橫向窄欄 |
| 主線目標 | 指揮條下方，右側保留快捷欄安全距離 | 單行省略只可用於次要目標，不能蓋到按鈕 |
| 右側快捷 | safe-top 起算的獨立垂直欄，最多 4 個＋更多 | 48px 觸控目標；更多是清單抽屜，不再疊第二排小 icon |
| 底部指揮甲板 | safe-bottom 之上；資源列 58px、導覽列 78px | 4 個資源槽＋首領鈕；五個導覽等寬，不縮成不可讀小字 |
| 命令面板 | safe 區內單一紙卷；64px 標題列＋唯一滾動內容區 | 內容不能用負 margin、絕對定位或 z-index 互蓋 |

### 18.3 任務列與操作契約

- 任務列固定為 `badge → main → action` 三欄；主內容再分「名稱／狀態、進度條、進度／獎勵」。
- `日`／`週` 是獨立徽記，不可漂在卡片邊緣；領取按鈕永遠單行，不能以 `<br>` 拆成兩行。
- `進行中`、`可領取`、`已領取` 必須同時有文字與顏色／邊框狀態；disabled 按鈕提供完整 aria-label 原因。
- 360px 以下改為上下兩段（主內容後接全寬操作鈕），不縮小正文或觸控目標。

### 18.4 Surface、motion 與驗收

- 面板只使用紙卷底材；戰鬥 HUD／資源／導覽只使用鐵木底材；朱砂只留給主要 CTA、危險與首領。
- 面板進出 220ms；按壓為短促位移／縮放；不可讓所有元件持續呼吸或發光。`prefers-reduced-motion` 時改為近瞬切換。
- 每次 UI 改動至少驗收 390×720、430×932、320×568 與短高橫向；檢查面板、任務列、頂欄、右欄、資源列、底欄的 bounding boxes 不互相重疊。
- 固定尺寸自動化只能證明幾何與可操作性；美術質感仍需截圖／實機人工確認，不能以 CSS 或檔案存在冒充完成。
- 主公牌與小尺寸武將頭像使用完整肖像縮放（contain）並保留深色底材；禁止以 cover 裁掉頭盔、鬍鬚或肩線。
- 角色審視至少抽查步兵、騎兵、謀士與長角色名；確認角色名、兵種、戰法、裝備、緣分與底部操作列均在自己的欄位內，無模糊、縮小到不可讀或互相蓋住。

### 18.5 入口唯一性與頁面責任

- 主公牌只開啟「主公軍府」；軍府只管理主公身份、稱號與頭像框，摘要數字是不可點擊的狀態資訊。
