# 三國：群英再起遊戲美術規範

狀態：MANDATORY STANDARD。這是角色、環境、UI、圖示與 VFX 的視覺方向，不記錄素材完成率。實際資產狀態見 [目前遊戲規格](../specs/current-game-spec.md)，待製作項目見 [目前工作清單](../work/active-backlog.md)。

## 核心方向

一句話：**古戰場像素軍帳 × 正統 16-bit 點陣像素名將（對標《桃園結義：放置三國RPG》）。**

三個視覺支柱：

1. 歷史重量：使用鐵灰、木褐、米金、朱砂、暗玉與宣紙色，避免霓虹科技感。
2. 武將辨識：角色以精緻 16-bit 點陣像素全身立姿（Pixel Art Chibi Heroes）、細膩光影階調、扎實著地與專屬兵器建立清楚輪廓。
3. 軍帳材質：介面像軍令、木案、紙卷、朱砂印與青銅器，不像 SaaS dashboard。

## 戰鬥角色

- 核心對標：**《桃園結義：放置三國RPG》（Three Kingdoms: Idle RPG）** 實機點陣像素標準。
- 完整全身精靈：從頭盔、五官、肩鎧、胸甲、戰裙到雙腿戰靴，扎實著地。
- 每個主要部位使用亮部、固有色、暗部三階點陣陰影，光源方向一致。
- 兵器自然融入角色手部與攻擊動作，揮砍時由粒子引擎渲染動態刀光弧線（Slash Arc）。
- 每名武將至少有三個身分錨點：剪影、臉部特徵、服裝／兵器特徵。
- idle、move、attack、hit、death 要保持同一身形、錨點與材質語言。
- 核准戰場動作圖以 96px cell 為基線；劉備、關羽、張飛、趙雲的高精度試製使用 128px cell，保存臉、鬍鬚、甲片、衣褶、握持與兵器輪廓。禁止先壓成 64px 再放大到戰場尺寸。
- move 必須看見左右腳接地與重心通過，披風、鬍鬚、袖口與兵器做次級延遲；禁止靜態雙腿配合整張 body 上下彈跳或滑行。
- 禁止用粗糙幾何方塊、樂高積木、半身大頭貼或換色大眾臉當作核心角色、普通敵人或 Boss 的正式完成品。

戰鬥人物的 ImageGen 提示、母圖格位、去背、切格、命名與重建流程以 [戰鬥人物圖片製作方式與規格](combat-character-asset-production.md) 為準；資產尺寸、層級與生命週期以 [戰鬥角色渲染契約](combat-character-render-contract.md) 為準。

## 頭像

- 基準 64×64 透明角色資產；UI 可裁切到所需尺寸，但不得拉伸。
- 保留角色的剪影、臉部標記與服裝色塊，縮圖仍要可辨識。
- 陣營底色與品質框只能輔助，不能取代角色本身差異。
- 金屬、眼神與鬍鬚等細節以精緻高光表現。

## 武器、裝備與道具圖示

- inventory icon 與 combat weapon 是兩套用途；卡片底框圖示不得直接放大進戰場。
- 圖示以 48×48／64×64 居中，保留安全邊界、輪廓與材質高光。
- 品質使用白灰、綠、藍、紫、橙金五階；同時配合名稱、框形或標籤，不能只靠顏色。
- 神兵可以有短促微光或粒子，但不能常駐大範圍呼吸搶走角色焦點。

## UI 與環境

- 戰鬥 HUD 使用鐵木；詳情與設定使用軍帳紙卷；主要 CTA 使用朱砂；獎勵與戰報使用深色金線。
- 面板材質與角花要服務層級，不可用大量紋理降低文字對比。
- 地形、天候與前景裝飾維持寫實尺度，保持視覺和諧。
- 背景對比低於角色，戰鬥熱區不放高對比裝飾或大型文字。

## VFX 與音畫聯動

- 攻擊與受擊以白光、火星、暗紅打擊環與紙碎／墨痕為主；不用多色霓虹光圈。
- 刀光、劍氣與弓箭必須有發射源、速度感與命中受擊幀。
- 技能特效只在發動瞬間點亮；殘留粒子要在 0.3 秒內淡出，不可持續遮擋戰場。
- 首領登場、關卡破關使用全螢幕暗角或戰場微震，不額外新增覆蓋主操作的無效等待。

## 審查清單

1. 抽離所有色彩後，主次層級是否依然清楚？
2. 是否有任何素材使用非三國的現代科幻／霓虹元素？
3. 武將與敵將能否在 0.5 秒內單憑剪影或配色認出？
4. 任何裝飾性邊框是否遮擋血條、數值或按鈕可點擊區？
5. 實機渲染在低亮度和強光環境下是否皆可閱讀？

## 違規判定

以下情況視為違反美術契約，必須在下一版前修正：

- 出現任何 debug 方塊、未替換的灰色 placeholder、灰綠／褐色矩形底塊、棋盤殘影或透明切邊穿模。
- 戰鬥武將與敵將僅靠換色區分，缺乏專屬剪影與特徵。
- HUD 覆蓋層遮擋主要戰鬥熱區超過 0.8 秒。
- 混合了不同光源方向或比例失調的資產。
- 同類資產同時出現未經整合的照片與不同光源。
- 用「已產生檔案」代替輪廓、握點、動畫與實機畫面的驗收。
- 在規範中勾選 `[x]` 宣稱全專案素材完成。

## 美術驗收

資產交付需同時通過：格式／尺寸／alpha 自動檢查、runtime 實際消費、固定尺寸截圖、角色與兵器逐狀態檢查，以及整體風格一致性評審。判定方式見 [視覺驗收規範](../qa/visual-qa.md)。
