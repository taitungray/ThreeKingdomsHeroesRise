# 無障礙與行動裝置規範

狀態：以 WCAG 2.1 AA 為產品目標，不宣稱已取得認證。每項完成都需要瀏覽器或實機證據，不能只靠 HTML 中存在一個 ARIA 屬性。

## 1. 目前已確認與缺口

已確認：`html` 使用 `zh-Hant`；主要彈窗具 `role="dialog"`、`aria-modal`、`aria-labelledby`；部分對話、toast、面板內容使用 `aria-live`；樣式保留 `focus-visible` 與 `prefers-reduced-motion`。

仍缺少完整證據：所有彈窗的 focus trap 與關閉後焦點返回、Canvas 戰鬥的文字替代、右側快捷與自訂狀態的 ARIA 同步、完整鍵盤路徑、AA 對比量測、TalkBack／VoiceOver 實機流程。未驗證前不得標示「AA 已通過」。

## 2. 語意與非文字內容

- 每個按鈕、圖示按鈕、資源與狀態都要有繁體中文可理解名稱；裝飾圖層使用 `aria-hidden="true"`。
- 選取、展開、按下、鎖定、停用、載入、已完成與已領取同步 `aria-selected`、`aria-expanded`、`aria-pressed`、`disabled` 或對等語意。
- 不用顏色作為唯一提示；名稱、圖形、位置或文字至少再提供一項差異。
- Canvas 需有整體可理解標籤；波次、敵人數、首領、勝敗與可操作技能另由 DOM／live region 提供文字，不要求讀屏解析像素畫面。
- 動態戰報使用適當 `aria-live`，高頻傷害數字不逐筆朗讀，避免讀屏被洗版。

## 3. 鍵盤、焦點與彈窗

- 所有互動控制項可用 Tab 到達並以 Enter／Space 操作；focus-visible 外框不得移除。
- 開啟面板或 modal 後焦點移至標題或第一個合理控制項，Tab／Shift+Tab 留在 modal 內。
- Escape 關閉最上層可關閉介面；關閉後焦點回到原觸發按鈕。教學或不可逆確認若禁止 Escape，要提供明確可見替代操作。
- 隱藏介面不可殘留在 tab order；disabled 需有原因文字或可讀說明，不只降低 opacity。
- Canvas 的桌面拖移不得觸發圖片原生拖曳或選取頁面文字；鍵盤仍需有等價操作。

## 4. 可讀性與對比

- 正文與必要說明至少 14px；主要按鈕與重要數值至少 16px；必要資訊不得放在 12px 以下。
- 一般文字與背景對比至少 4.5:1；大字至少 3:1；焦點、元件邊界與非文字狀態至少 3:1。
- 文字放在戰場上時使用實色底、描邊或足夠遮罩；不能只靠陰影勉強辨識。
- 支援 200% 縮放時仍可操作；必要資訊不裁切、不水平捲動整頁、不彼此重疊。

## 5. 觸控、方向與安全區

- 主要互動控制項最小 44×44 CSS px，控制項之間保留可避免誤觸的間距。
- 不依賴 hover、雙擊或精準拖曳；拖曳功能要有點選式替代方案。
- 使用 safe area；直式鎖定時提供旋轉提示，320×568 與短高橫向不可讓資源或主要 CTA 被裁切。
- 觸控、滑鼠、鍵盤不能重複觸發同一獎勵或操作。

## 6. 動畫、震動與音訊

- 尊重 `prefers-reduced-motion`：關閉裝飾粒子、常駐脈動、全畫面震動與不必要過場，保留必要狀態結果。
- 不呼叫 `navigator.vibrate`；瀏覽器未經手勢的震動會造成 console 噪音，也不是必要戰鬥回饋。
- 閃爍不得超過每秒三次；快速白閃、紅閃或全畫面 flash 需有 reduced-motion／reduced-effects 降級。
- 音效與音樂可獨立關閉；關鍵狀態不能只靠聲音傳達。

## 7. 驗證方式

1. Chrome 鍵盤走完登入、戰鬥、五個底欄、右側軍務、面板與結算。
2. 檢查每個 dialog 的初始焦點、focus trap、Escape 與焦點返回。
3. 使用瀏覽器 Accessibility tree 檢查名稱、角色、狀態與 live region。
4. 以對比工具量測正文、次要文字、按鈕、焦點與 disabled；保留數值證據。
5. 在 200% 縮放、390×720、320×568、430×932、短高橫向檢查裁切。
6. 模擬 `prefers-reduced-motion: reduce`，確認可操作性與結果不變。
7. 發布前至少各做一次 Android TalkBack 與 iOS／PWA 可行範圍的 VoiceOver 人工流程；未執行要明列。
